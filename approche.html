Un code est le début. Pas la réponse.

L’ambition est simple : rendre le raisonnement derrière un résultat de diagnostic aussi visible que le résultat lui-même. La configuration du véhicule, la provenance des sources et les preuves passent avant toute explication par l’IA.

Contexte. Preuves. Clarté.

Un dossier, annoté. Chaque principe d’ORVECT agit sur une ligne précise.

Contexte

Le bon véhicule. Le bon périmètre.

Garder visibles le véhicule, le moteur, le calculateur et l’espace de diagnostic. Une correspondance incertaine reste incertaine.

Preuves

Montrer la source. Respecter les limites.

Préserver la provenance et la compatibilité. Une définition indisponible est signalée comme telle.

Moteur de diagnostic

Les preuves avant les hypothèses.

Un état de diagnostic structuré, une ambiguïté explicite et aucune obligation de produire une réponse. Zéro hypothèse est un résultat valable.

Moteur de sécurité

Prudent par conception.

Les limites critiques relèvent de règles, pas du modèle. Sans règle fiable : indéterminé, revue humaine.

Clarté

Le langage, pas l’autorité.

Le modèle explique le raisonnement dans ces limites. Il n’autorise ni la conduite ni un remplacement définitif : le technicien garde la main.

L’intelligence. Avec une structure.

Trois couches distinctes dans une application modulaire. La fluidité ne remplace pas les preuves.

  1. Couche d’explicationLe langage, pas l’autorité.
  2. Moteur de sécuritéDes règles déterministes, appliquées après la réponse du modèle.
  3. Moteur de diagnosticLes preuves avant les hypothèses.
